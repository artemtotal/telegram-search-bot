## Модель цены: два вопроса вместо четырёх

Раньше мастер спрашивал цену до четырёх раз — отдельно под Kaltmiete, под
Gesamtmiete ProPotsdam, под цену Kleinanzeigen и под Warmmiete Karl Marx.
Величин на самом деле две, и каждый портал знает хотя бы одну:

- `KALTMIETE_SOURCES` и `WARMMIETE_SOURCES` в `user_handlers/housing_monitor.py`
  перечисляют, кто какую публикует;
- `_price_steps_for()` показывает вопрос, только если хоть один из выбранных
  порталов действительно печатает эту величину;
- в фильтрах два поля границ: `min/max_price_eur` (холодная) и
  `min/max_price_warm_eur` (полная).

Главное правило сопоставления: **если у объявления нужной величины нет, граница
просто не применяется** (`_within_min/_within_max` пропускают `None`). Квартиру
нельзя выбрасывать за число, которого портал не публикует.

## Vonovia: как он появился и что в его данных

**Повод.** 2026-09-02 боту пришла с Immowelt однокомнатная на
Erich-Weinert-Straße 16 (263 € Kaltmiete, 25,8 м²). В карточке выдачи Immowelt
имени арендодателя нет текстом — оно в `alt` логотипа: «Vonovia Kundenservice
GmbH». Открыть само Exposé не удалось: прямая ссылка отдаёт **403** и обычному
`requests`, и настоящему Chrome со свежим профилем, тогда как страница выдачи
открывается нормально.

**Находка.** Запись «Vonovia — только через мобильное приложение, простым
скрейпером не взять» оказалась устаревшей. У них обычный веб-поиск:

- страница выдачи — GET-форма: `https://www.vonovia.de/zuhause-finden/immobilien?rentType=miete&city=Potsdam&immoType=wohnung`
- данные — открытый JSON: `GET https://www.vonovia.de/api/real-estate/list?limit=15&offset=0&rentType=miete&city=…&immoType=wohnung`
- **но только с сессии**: сначала GET страницы выдачи (за кукой), потом запрос с
  `Referer` и `Accept: application/json`. Без этого приходит **406** — без тела,
  и легко принять за поломку.

Поля объекта: `wrk_id` (ключ), `titel`, `strasse`, `plz`, `ort`, `preis`
(Kaltmiete), `groesse`, `anzahl_zimmer`, `imageUrls`, `slug`. Страница
объявления (`/zuhause-finden/immobilien/<slug>`) несёт весь свой JSON в атрибуте
`data-vonovia-data` в HTML-экранированном виде: `rent`, `warmRent`,
`operatingCosts`, `heatingCosts`, `securityDeposit`, `images`, `sections`.

**Три ловушки, все закрыты тестами:**

1. **Гаражи в одной выдаче с квартирами.** Приходят с нулями в площади и
   комнатах. Без отсева человеку ушла бы «квартира» за 44 € без единой комнаты.
   Запрос идёт с `immoType=wohnung`, и нули отсеиваются ещё раз на нашей стороне.
2. **`anzahl_zimmer` округляет вниз.** «2,5-Zimmer-Wohnung» приходит как `2` —
   полкомнаты не в пользу человека на границе фильтра. Точное число берётся из
   заголовка.
3. **Реклама в галерее.** Рядом с фото квартиры лежат картинки кампаний
   (`CAMP-*.jpg` — реклама приложения, «зелёный ток»); отсеиваются по имени
   файла. Фото запрашиваются в полном размере (`?width=1200`), а не превью 324 px.

**Почему источник сейчас молчит.** По Потсдаму у Vonovia **ноль квартир**: все
25 их местных позиций — парковочные места и одна коммерческая площадь. Фильтр по
типу работает, проверено контрольными городами: Берлин 13 квартир, Бохум 92. Свои
потсдамские квартиры Vonovia отдаёт на порталы — та самая с Erich-Weinert-Straße
пришла через Immowelt. Источник добавлен на будущее и ничего не стоит, пока
инвентаря нет.

**Проверено на живых данных** (Бохум как контрольный город): 93 квартиры за семь
страниц, галереи на месте, полная аренда дозабирается —
Weitmarer Str. 145 a: 841,89 → 1111,89 €; Kaulbachstr. 4: 761,40 → 919,40 €.
В боевом контейнере первый обход: `Vonovia scan total=0 stored=0 full_rent=0`,
статус `ok`.

## Как добавить источник — чеклист

Проверен на Vonovia; ничего нового изобретать не надо, но точек больше, чем
кажется.

**Новые файлы** (по образцу `locals_*`, а если у источника есть галерея в
каталоге — `vonovia_*`):
`user_jobs/<name>_parser.py`, `_matching.py`, `_store.py`, `_monitor.py`.

**Правки:**
1. `database.py` — четыре модели: `…Listing`, `…Filter`, `…Status`, `…Delivery`.
2. `robot.py` — импорт и `job.run_repeating(...)`; `first=` на 30 секунд позже
   предыдущего источника, чтобы обходы не сходились в одну секунду.
3. `user_handlers/housing_monitor.py` — около двадцати мест: импорт,
   `<NAME>_CRITERIA_FIELDS/KEYS/BY_KEY`, `AVAILABLE_SOURCES`,
   `KALTMIETE_SOURCES`/`WARMMIETE_SOURCES`, `_LOCAL_SOURCE_MODULES`,
   `ALL_HOUSING_SOURCES`, обе функции сбора фильтров пользователя,
   `_GENERIC_STATUS_SOURCES`, буква-префикс фильтра, список для админа,
   два кортежа массовых операций (пауза/удаление), `SOURCE_ICON`,
   `SOURCE_LABEL`, `_SOURCE_ORDER`, диспетчеры «включить/удалить»,
   `start_<name>_edit_flow` + `_finalize_<name>_filter` + `_handle_<name>_flow`,
   их три диспетчера (режим, шаг назад, кнопка «править») и ветка создания в
   общем мастере.
4. `translations/{uk,ru,de}.json` — счётчик порталов и перечисления в
   `housing.menu.intro`, `housing.locked.text`, `housing.faq.text`. Все три языка
   обязательно: `tests/test_i18n.py` падает на расхождении ключей, но за
   содержимым текста он не следит.
5. Тесты: парсер, хранилище, монитор + проводка в `tests/test_housing_monitor.py`.
   Не забыть счётчики в существующих тестах (`ALL_HOUSING_SOURCES`, «N порталами»).

## Как гонять тесты и выкатывать

```
# весь набор — внутри контейнера, но сначала пересобрать образ
docker compose build tgbot && docker compose up -d tgbot
docker exec tgbot python -m unittest discover -s tests -q

# быстрый цикл по одному модулю — на хосте (там свой Python с sqlalchemy);
# годится для парсера и хранилища, но не для всего, что тянет telegram:
# на хосте PTB 22.x, а бот живёт на 13.15
python -m unittest tests.test_vonovia_parser
```

Коллектор ProPotsdam живёт отдельно от контейнера — после правок в
`tools/propotsdam_receiver.py` его нужно перезапускать руками на хосте, см.
память `project-propotsdam-collector-operations`.

## Нерешённое

1. **Фотографии ProPotsdam отдают 404.** Идентификаторы `api5/accndocs2/<resourceId>`,
   взятые из XML списка, не открываются даже под логином, хотя сам портал по тому
   же адресу свои картинки отдаёт. Объявления оттуда сейчас приходят без снимков.
2. **Подписи полей в уведомлениях захардкожены по-украински.** В
   `format_listing_message` каждого парсера («Назва», «Адреса», «Кімнати») — они
   не проходят через `i18n.t`, так что немецкоязычный получатель видит их
   по-украински. Тексты самого мастера локализованы полностью.

## Что менялось в начале сентября 2026

- Цена сведена к двум вопросам (Kaltmiete + Warmmiete) вместо четырёх; вторые
  цены добавлены во все восемь тогдашних источников.
- Immowelt: подпись под ценой больше не игнорируется — `price_basis`
  (`kalt`/`warm`) идёт из карточки через приёмник до бота, и объявления с
  Warmmiete не сравниваются с холодной границей.
- Kleinanzeigen: восстановлен разбор после редизайна (плюс `apparent_encoding` —
  без него страница парсилась в мусор) и добавлена галерея вместо одной обложки.
- ProPotsdam: починены логин, навигация и снимок карточки; цены из блока
  «Kosten» доходят до базы; `DETAIL_MAX_PER_SCAN` поднят с 3 до 10, чтобы
  четыре новые квартиры за один обход не приходили без холодной цены.
- Добавлен девятый источник — Vonovia.
